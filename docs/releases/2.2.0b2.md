# aNEOS 2.2.0b2 — engineering test preview

This prerelease lets you test the integrated per-object acquisition, local evidence,
screening and reporting work. It is not a scientifically calibrated detector or a
claim that every legacy feature is complete. Not flagged does not mean natural.

## Changes since 2.2.0b1

- Polling no longer discards later source payloads for an existing designation.
- Exact-repeat handling stays in the transactional ledger; conflicting/complementary
  payloads and differing epochs remain in source history.
- A failed or unacknowledged commit prevents dashboard publication.
- Returned record counts, distinct exact designation labels and source outcomes are
  separate. Returned rows do not establish live retrieval or scientific completeness.

These paths were tested with synthetic providers and disposable file-SQLite databases.
Live bulk source discovery is still quarantined; the per-object query remains the
intended beta test workflow. Existing beta data are not migrated or overwritten.

## Install separately

Use Python **3.11** and a new checkout. Do not pull this over a dirty research working
tree, reuse a production database, or replace an earlier investigation directory.
The commands below create a separate database for the beta; they do not migrate or
back up an existing database.

```bash
git clone --branch v2.2.0b2 https://github.com/RobLe3/aneos-suite.git aneos-suite-beta
cd aneos-suite-beta
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-core.txt
mkdir -p beta-runtime
export ANEOS_DATABASE_URL="sqlite:///$PWD/beta-runtime/aneos-beta.sqlite"
python aneos.py --version
```

Expected version: `aNEOS 2.2.0b2 (beta)`. The source distribution runs from this checkout;
there is no new PyPI package to install. Optional full ML dependencies are separate
from the core profile and do not establish detection accuracy.

## First tests

### Interactive menu

```bash
python aneos.py
```

The main menu, scientific help, canonical object details, current analysis-policy
inspection and the corrected results dashboard are useful starting points. Record
the option, designation and output when reporting a problem. Not every legacy menu
option has completed behavioral QA; the inventory remains tracked in #41.

### One real per-object query

```bash
python aneos.py analyze "1998 KY26" --json --output beta-runtime/ky26.json
python aneos.py analyze "1998 KY26"
```

A query uses the installed source profile and commits its source outcomes to the
separate local SQLite ledger before returning evidence. Provider outages, empty
responses and missing measurements remain explicit. Source/profile coverage and
field presence are not 100% scientific completeness. Do not add `--force-refresh`
unless you intend another adapter query; it still does not guarantee a new wire
response when a provider SDK uses its own cache.

The original November 12 historical score is not overwritten or declared exactly
reproduced. Current results identify their own evidence/software versions. Raw rank
is not sigma, a p-value or an artificial-origin probability.

### Dashboard from a saved source-bearing result

```bash
python artificial_neo_dashboard_launcher.py --file beta-runtime/ky26.json
```

Inspect the source/field inventory, explanation and ranking trace. New dashboard
exports are written into exclusive directories under `dashboard_results/` with JSON,
Markdown and a completion/hash marker. Import does not rewrite the input file.
Raw legacy probability-only files are retained as unverified assertions, not adopted
as measured data or origin classifications.

### Local API

```bash
python aneos.py api --dev --host 127.0.0.1 --port 8000
```

Use `http://127.0.0.1:8000/` for application identity and `/docs` for the generated API
schema. Keep this beta bound to localhost. General authentication and multi-user
production deployment have remaining work (#47); development tokens are not authority
for durable jobs. The supported evidence/job persistence path for this preview is
file-backed SQLite. The Docker build check does not certify the default PostgreSQL
Compose deployment as an equivalent validated evidence backend.

## Known limits

- **Root legacy candidate polling/inference is temporarily unavailable.** Known-bad
  entry points fail explicitly before provider access or synthetic/missing-as-zero
  inference. Their source restoration remains tracked in #73. The #71 workflow
  correction preserves all returned source payloads in the existing ledger before
  presentation, but does not restore bulk polling. The dashboard can inspect older
  files as unverified input. The ordinary
  typed per-object query is the intended test path for this preview.
- Automatic selective partial-cache backfill, exhaustive source/field coverage and a
  global alias registry remain incomplete. Missing data are never silently zero.
- The ranking retains its documented prototype population/feature-dependence limits.
  There is no independent Gaussian significance, calibrated posterior/FDR, physical
  origin comparison or search-wide five-sigma claim.
- Complete observational fits, independent controls, the exact original KY26 input
  baseline and full documentation/menu QA remain open. This beta is not the final
  scientific deliverable requested in programme #2.
- File/JSON preservation is scoped to the described read/append/export operations.
  Cache eviction, later manual edits, cleanup, synchronization and deletion can still
  change local artifacts. Keep a separate backup of important original research.

## Report a beta result

Include the version, command/menu path, object designation, source/query/report IDs,
expected versus actual behavior and a redacted JSON/Markdown example. Do not attach
credentials, private observations or databases without reviewing their contents and
redistribution rights. A known missing measurement is different from an application
error; report which one you observed.

Earlier engineering notes describe their draft-state snapshots; this beta integrates
the implemented stack without turning those historical notes into scientific validation.

Integration CI, clean-install smoke results, the merged PR and the release tag are
linked in the GitHub prerelease notes. Test counts are engineering evidence, not
independent scientific certification.

### Archive versus checkout

The attached source archive omits the mutable root `.env` and `aneos.db` through
export rules. Git checkouts/history retain those pre-existing files; they are not
silently deleted or migrated. The beta commands explicitly select a new runtime
database instead. Neither approach is a backup of your current installation. Do not
replace your existing working directory or copy its database over the beta database.

Large source-bearing dashboards can be slow because full reviews are checked repeatedly.
Start with per-object/small views; the measured rendering follow-up is tracked separately.
Runtime exports under `beta-runtime/` and `dashboard_results/` are ignored by Git to
avoid accidentally publishing research data; this does not delete or back them up.
